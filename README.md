# sunzi: 用孫子算局面的方式, 陪經營者看清決定卡在哪裡

一個 Claude Skill. 它不引用 "商場如戰場" 的名句, 而是借用孫子 "怎麼算局面": 在出手之前看清楚, 這一仗該不該打, 能不能打, 怎麼打代價最小. 給的是一個沒想到的角度, 不是策略框架或 SOP.

產品構想與設計取捨見 [Develop.md](Develop.md).

## 使用方式

### Claude Code

在此 repo 目錄啟動 Claude Code, skill 會自動載入.

想確定用到這個 skill, 輸入 `/sunzi` 再描述卡住的決定. 直接描述也可以, 但不一定會觸發.

### claude.ai

上傳 `dist/sunzi.skill`, 或將 `.claude/skills/sunzi/` 資料夾壓成 zip, 在 claude.ai 的 Skills 設定中上傳.

### 觸發行為

實測 20 個提問, 每題 2 次 (見 `sunzi-workspace/trigger/`):

- 該觸發的經營問題: 約 45% 的次數會自動觸發, 10 題中有 7 題至少觸發一次.
- 不該觸發的提問: 0 次誤觸發. 包括算毛利, 寫孫子兵法主題的貼文, 作者考證, 遊戲攻略, 合約法條, 感情問題.

自動觸發率不高的主要原因, 是 Claude 遇到自己能直接回答的問題時, 通常不會去調用 skill. 曾嘗試用 skill-creator 的自動優化改寫描述, 改出的版本越來越強勢, 會讓 skill 攔下幾乎所有商業對話, 召回率卻沒有明顯提升, 因此保留原本的描述. 需要這個視角時, 用 `/sunzi` 呼叫最可靠.

## 設計重點

### 5 個心智模型

多算勝, 先為不可勝, 避實擊虛, 求之於勢, 不戰而屈人之兵. 每個模型都寫明 "什麼時候不該用", 例如:

- 窗口正在關上時, 不用 "多算勝" 要求更多調研.
- 本業結構性衰退時, 不用 "先為不可勝" 合理化原地不動.

### 8 類經營情境, 40 句原文

開戰與否, 看不清局, 以小搏大, 消耗戰, 決策衝動, 組織與授權, 危機與轉型, 勝出之後, 每類 5 句. 分類只是找句子的索引. Claude 先看卡點的形狀: 算得太少, 衝得太快, 打錯了戰場, 還是根本不該打這一仗.

### 回應的樣子

- 第一則以 300 字內為目標, 最多引一句原文, 格式是 "篇名 (編號) 說 "原文"".
- 比喻從使用者的產業取材.
- 收尾在問題, 觀察, 比喻之間輪替, 不用固定句式.
- 不給步驟清單, 不列選項, 不代寫台詞.

### 反駁檢查點

- A. 判斷錯了: 使用者補了新事實, 說出哪裡錯再修正.
- B. 只是不同意: 沒有新資訊, 換個比喻, 不改口.
- C. 不適合用孫子看: 需要財務, 法律或陪伴時直接說, 開場看得出來就在第一則說.
- 越界要求: 營業秘密, 對員工說謊, 聯合定價, 散布不實資訊等, 直接拒絕並說明原文為何不能這樣延伸.

### 不讓孫子變成不擇手段的藉口

- 先確認對方是不是敵人. 市場通常不是零和.
- "兵者詭道", "親而離之", 用間篇, 九地篇的治兵段落, 有明確的選句禁區.
- 決定碰到法規時, 主動用一句話提醒並轉介專業.

## 驗證

```
python scripts/verify_skill.py
```

檢查 skill 內所有引文是否逐字存在於原文且段落編號正確, 原文副本是否與 `references/sunzi.md` 一致, 示範回應是否只引一句, 以及標點格式.

盲測方式與歷次結果見 `tests/runs/`. 摘要:

| 測試 | 受測對象 | 結果 |
| --- | --- | --- |
| 主測試集 14 題, 三輪調整 | Develop.md | 68/70, 68/70, 70/70 |
| holdout 第一組 8 題 | Develop.md | 39/40 |
| 有無 skill 對比 4 題 | skill | 通過率 95% 對 55% |
| holdout 第二組 8 題 | skill | 40/40 |

評分由開發過程中的 Claude 執行, 評分者看過預期答案. 真實使用者的回饋尚未納入.
